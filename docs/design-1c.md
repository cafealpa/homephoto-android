캔버스 링크가 바뀌어도 구현 근거가 남도록 여기에 적어 둔다. 상위 문서: [UI.md](UI.md).

## 구현 시 주의

- **1c는 하단 내비게이션이다.** 애초 요청의 "TabRow 유지" 조건과 어긋나므로 `MainActivity`의
  `TabRow`를 하단 바로 교체해야 한다.
- `backdrop-filter: blur(20px)`는 Compose에 직접 대응이 없다. 사진이 바 뒤로 흐려 보이게 하려면
  별도 처리가 필요하다. Scaffold 가 바 높이만큼 본문을 줄여 바 뒤로 지나가는 사진이 없으므로
  반투명도 화면상 의미가 없어, **불투명 화면색**으로 구현했다.
- `LazyVerticalGrid`는 **행 span을 지원하지 않는다**(`GridItemSpan`은 열만). 대표 2×2 타일은
  4열 전체를 차지하는 항목 하나 안에 `Row { 대표 정사각 + Column { 작은 셀 2×2 } }`로 만든다.
- 사진 칸은 목업에서 `#1c1c22`~`#34343d` 범위의 회색 플레이스홀더다 — 실제로는 썸네일이 들어간다.

적용 완료: 하단 내비게이션, 월 칩, 대표 2×2 타일, 월 헤더, 카드(#17171A + 1px #232326 + 12dp),
채움/테두리 버튼, 실패 이력 카드, 요약 카드 색 구분. 다크 전용으로 고정(라이트 스킴 제거).

미적용:

- **월 칩과 대표 2×2 타일은 실제 사진이 있어야 보이므로 화면으로 확인하지 못했다.**
  묶음 규칙은 `app/src/test/.../ui/TimelineCellsTest.kt` 단위 테스트 7건으로 검증.
  서버를 붙인 뒤 실기기에서 눈으로 한 번 확인할 것.

### 알려진 에뮬레이터 표시 이상 (앱 버그 아님)

에뮬레이터 스크린샷에서 하단 내비게이션의 **글자만** 화면 상단(상태바 아래)에 한 벌 더
그려져 보인다. 다음을 확인해 앱 레이아웃 문제가 아니라고 판단했다:

- `uiautomator dump`상 내비게이션 노드는 화면 하단(`y 2217~2340`)에 **한 벌만** 존재
- `dumpsys SurfaceFlinger`상 앱 레이어도 전체화면 한 장뿐
- 유령 이미지에는 배경과 상단 경계선이 없고 **글리프만** 복제된다
- 반투명 제거·`Surface` 제거·완전 재설치 후에도 그대로 남는다

글리프 캐시 쪽 렌더 이상으로 보인다. 실기기에서 재현되는지 확인이 필요하며,
재현된다면 그때 원인을 다시 파악한다.
